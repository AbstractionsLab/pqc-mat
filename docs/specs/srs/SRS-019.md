# Provide a script to build and run VECTOR in CLI or GUI mode

VECTOR SHALL provide a single runner script, at the repository root, that builds the standalone container image and starts it in CLI mode or GUI mode as selected by the operator, without requiring the operator to compose `docker build`/`docker run` commands directly.

## Rationale

A single runner script that builds the image and lets the operator choose CLI or GUI mode gives VECTOR the ease of use outside the Dev Container.

## Acceptance criteria

- A build script at the repository root builds the standalone container image; a separate run script starts a container from it. Rebuilding the image does not require also starting a container.
- The operator can explicitly choose CLI mode or GUI mode when using the run script; GUI mode is the default when no mode is given.
- In GUI mode, the script starts VECTOR GUI and reports the local address to open in a browser.
- In CLI mode, `vector code`, `vector network`, and `vector score` commands are forwarded to the container as given.
- The `vector` CLI provides a way to start the GUI directly. For example, a `vector gui` command or a `-g` option, so the run script can reach the GUI the same way it reaches the CLI, without needing to override the container's entry point.
- Before starting a container, the script confirms the required image has already been built.
- When a `vector` command is given a source or output folder as an argument, the run script confirms it exists on the host before mounting it; if it does not, the run script stops with a clear, actionable message and does not start a container.
- The script requires only Docker and a POSIX shell on the host.
