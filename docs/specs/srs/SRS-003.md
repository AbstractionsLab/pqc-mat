# Create CodeQL databases through the CodeQL CLI

VECTOR-Code SHALL invoke the external CodeQL CLI to create one analysis database per detected CodeQL language, extracting the source files directly without running any build.

## Rationale
Leveraging CodeQL tooling for cryptographic inventory queries.

Analyzed projects do not necessarily have a build system or they might need specific dependencies; to avoid database creation failures due to build errors, databases have to be created with `--build-mode=none`. In this mode, CodeQL infers the compiler settings that a build would provide (e.g., include paths and macro definitions) from the source files directly. As a consequence, for C and C++ a call to a cryptographic library is only recognized when the header declaring it can be resolved without compiling. Since CodeQL queries support OpenSSL, the VECTOR image must install the OpenSSL development headers, so that OpenSSL includes resolve even when the project does not ship the headers or finds them through its own include paths. In no build mode does CodeQL analyze object code or binaries; only source files are extracted.

## Acceptance criteria
- Duplicate source languages that map to the same CodeQL language do not create redundant databases.
- Database creation uses `--build-mode=none`, so no build command of the analyzed project is executed.
- Failed database creation for one language does not create a successful result for that language.
